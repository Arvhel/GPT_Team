# Sprint 1 — Team Working Agreement and Definition of Done

## Objective

Establish a shared working agreement, clarify team responsibilities, and define completion standards for the HOPE, Inc. ERP System development team.

## Team Working Agreement

The team agreed to follow these general collaboration guidelines:

- Communicate task updates and concerns with the team.
- Complete assigned tasks within agreed deadlines whenever possible.
- Ask for clarification when requirements are unclear.
- Keep GitHub Issues updated to reflect task progress.
- Use feature branches when working on changes.
- Submit Pull Requests before integrating changes into the main branch.
- Review and test changes before considering work complete.

## Team Roles and Responsibilities

| Role | Main Responsibility |
|---|---|
| Scrum Master | Coordinate sprint activities, manage issues, and monitor progress. |
| Developer | Implement application features and fix technical issues. |
| UI/UX Designer | Design user interfaces and maintain consistency. |
| Database Administrator | Plan and maintain database structures and relationships. |
| Tester | Check completed features against their requirements. |

## Definition of Done

A task may be considered complete when:

- The assigned requirements have been addressed.
- The implementation follows the agreed project structure.
- Changes have been reviewed through a Pull Request.
- Required testing or validation has been performed.
- Identified issues have been addressed or documented.
- The related GitHub Issue and Scrum Board status have been updated.

## Expected Output

A shared understanding of team responsibilities, collaboration practices, and completion standards.

## Documentation Note

This document was prepared retrospectively to record the working agreement and completion guidelines established for Sprint 1.
