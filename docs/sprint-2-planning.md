\# Hope, Inc. – Sprint 2 Planning



\## 1. Sprint Goal



Implement Customer Management and Product Management features, including price history, database support, permission checks, and user interface improvements.



\## 2. Sprint 2 Scope



The following modules and tasks are included:



\- Customer Management

\- Product Management

\- Price History

\- Database Views and Validation

\- Search and Filtering

\- Role and Permission Checks

\- Testing and Bug Verification



\## 3. Team Responsibilities



| Role | Responsibilities |

|---|---|

| Scrum Master | Sprint planning, coordination, progress monitoring, and sprint review |

| Developer | Customer and Product Management implementation |

| DB Admin | Database views, queries, constraints, and optimization |

| UI/UX Designer | Wireframes, mockups, and usability review |

| Tester | Test cases, regression testing, and bug verification |



\## 4. Sprint Task Tracking



All Sprint 2 tasks will be monitored through GitHub Issues.



Each task should:

\- Be assigned to the appropriate team member.

\- Have the corresponding Sprint 2 task ID.

\- Be updated as work progresses.

\- Be linked to its Pull Request when submitted.



\## 5. Pull Request Workflow



1\. Team members create separate feature branches.

2\. Team members complete their assigned tasks.

3\. Changes are committed and pushed to GitHub.

4\. Pull Requests are submitted targeting the main branch.

5\. Changes undergo review and testing.

6\. Approved Pull Requests are merged into main.



\## 6. Scrum Master Responsibilities



\- Monitor Sprint 2 task progress.

\- Follow up on pending tasks.

\- Record team impediments.

\- Coordinate Pull Request reviews.

\- Maintain the Sprint 2 project board.

\- Prepare sprint review and retrospective documentation.



\## 7. Expected Outcome



By the end of Sprint 2, the team aims to deliver the planned Customer Management and Product Management functionality with supporting database operations, interface designs, and testing documentation.
