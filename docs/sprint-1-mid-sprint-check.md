# Sprint 1 — Mid-Sprint Check and Impediment Log

## Objective

Monitor the team's progress during Sprint 1, identify possible blockers, and coordinate actions needed to keep development tasks on track.

## Scrum Master Responsibilities

- Check the progress of assigned tasks.
- Review updates from team members.
- Monitor the status of GitHub Issues and Pull Requests.
- Identify delays and development difficulties.
- Coordinate with members when clarification or assistance is needed.
- Record impediments and follow-up actions.

## Progress Monitoring

GitHub Issues and the Scrum Board were used to monitor the progress of Sprint 1 tasks.

The Scrum Master reviewed task statuses to identify completed work, ongoing activities, and tasks requiring additional attention.

## Impediment Log

| Area | Details |
|---|---|
| Identified impediments | Record the actual blockers encountered during Sprint 1. |
| Affected tasks | Identify the related GitHub Issues or development tasks. |
| Action taken | Record the steps taken to address each impediment. |
| Follow-up | Record whether the issue was resolved or still required attention. |

## Progress Check Notes

The following information should be considered when reviewing Sprint 1:

- Completion status of assigned tasks.
- Updates and feedback from team members.
- Pending Pull Requests and code reviews.
- Issues requiring clarification or additional work.
- Tasks that needed follow-up before sprint completion.

## Expected Output

A record of Sprint 1 progress, identified impediments, and follow-up actions to support team coordination and project tracking.

## Documentation Note

This document was prepared retrospectively to record the Sprint 1 monitoring process. Specific blockers and actions should reflect the team's actual experience during the sprint.
