# Sprint 1 — Review and Retrospective Report

## Objective

Review the accomplishments, development progress, and challenges encountered during Sprint 1 of the HOPE, Inc. ERP System project.

## Sprint Review

The Sprint 1 review focused on evaluating the work completed by the team and checking whether the assigned tasks met their intended requirements.

The review considered:

- Completed development tasks.
- Submitted and merged Pull Requests.
- Progress of assigned GitHub Issues.
- Initial project structure and configuration.
- UI and database development progress.
- Items that required further development in the next sprint.

## Sprint Retrospective

The retrospective focused on identifying what went well, what needed improvement, and what actions could help the team work more effectively.

### What Went Well

- Team members had assigned roles and responsibilities.
- GitHub Issues helped organize development tasks.
- Branches and Pull Requests supported team collaboration.
- The Scrum Board provided visibility into task progress.

### What Needed Improvement

- Some tasks required additional coordination and follow-up.
- Communication and progress updates could be more consistent.
- Pull Requests and testing needed to be monitored regularly.
- Some features required additional development before they could be considered complete.

### Action Items for the Next Sprint

- Encourage regular progress updates from team members.
- Monitor assigned GitHub Issues more consistently.
- Review Pull Requests before merging into `main`.
- Coordinate testing and validation of completed features.
- Clarify requirements before development begins.
